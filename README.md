# 多源单调聚合 · 精确 Top-K 分析查询模块

排行榜总分来自多张表，业务键可能缺项或一对多。本模块不把各表前十名简单拼接，
而是实现一个支持**明确单调组合分数、关联粒度与缺项规则**的分析查询引擎，
在有限内存中给出与全量关联**逐名一致**的精确前 K 项，并记录真实读取量与可审计的停止证据。

零第三方依赖，仅用 Python 标准库（含 HTTP 服务与网页）。

## 它解决什么问题

朴素做法「每源各取前 K，再把局部榜单拼起来」是错的：一个在每张表都排第 4、
但没有明显短板的均衡型对象，组合总分可能高居总榜第 1，却永远进不了任何单源前列。
内置反例数据集 `counterexample` 中，`star` 在三个源都排第 4，等权加权和 2.25 却是总赢家，
朴素局部 TopK 必然漏掉它（见下文实测）。

## 核心设计

### 1. 数据模型与关联粒度（`leaderboard/sources.py`）

- 每个源由若干 `Row(key, score, row_id)` 组成，业务键 `key` 标识排行榜对象，同一键可有多行（一对多）。
- **一对多先归约再组合**：每个 `(源, 键)` 通过指定规则归约成一个标量，
  支持 `max / sum / avg / first`（`first` 按分数降序、row_id 升序稳定取首行）。
    归约后一个对象在一个源只占一个榜位，关联膨胀无法霸榜。
- 两种访问原语：**排序访问 SA**（按归约分降序逐行读）与**随机访问 RA**（按键取该键全部行）。
- `VersionedSource` 整体替换数据并递增版本；查询首次访问即固定不可变 `Snapshot`，
  从根上杜绝「半张新表半张旧表」的拼版读取。

### 2. 单调组合分数与缺项规则（`leaderboard/scoring.py`）

- 聚合器均为单调非降函数：`wsum`（加权和）、`min`、`max`、`product`，权重可配。
- 缺项规则：
    - `neutral`：缺席源取聚合器中性元（wsum=0、min=+∞、max=−∞、product=1），源仍占位；
    - `exclude`：缺席源移出组合，wsum 按在场源权重重新归一化。
- 稳定并列约定：分数在浮点容差 `EPS=1e-12` 内视为并列，并列时按业务键字典序升序，
    结果与访问顺序、源排列顺序完全无关。
- 上下界数学：`bounds()` 处理「未知源取 [0, dmax] 或缺席」；
    `nra_bounds()` 处理 NRA 下「未知源缺席，或在场且值不超过当前 SA 阈值」，
    两种可能都纳入枚举。上下界通过穷举未知源取值网格测试验证。

### 3. 执行器与可证明的提前停止（`leaderboard/engine.py`）

- **TA 模式**：每轮对一个源做一次 SA，随后对该键在其余未知源做 RA 立即补全；
    维护任何未见对象可达的上界 `UB_unseen`，只有当当前第 K 名的**确定**分数严格高于
    该上界（考虑并列 id 约定）时才停止。
- **NRA 模式**：只做 SA，为每个已见键维护 (下界, 上界) 区间；当临时前 K 名全部确定、
    且其余对象（含未见对象）的上界都严格低于第 K 名分数（区间闭包）时停止。
- 停止证据（阈值、未见上界、边界键与分数、停止规则）随每一步事件记录，可在网页逐步查看。
- 域上界从快照自动探测（用户显式配置优先），避免 sum 归约使分数超过默认 1.0 而低估上界。
- SA 调度支持 `round_robin` 与 `cheapest`（按源 SA 代价）；每源 SA/RA 次数、
    触及原始行数、虚拟耗时（含可模拟的源延迟）全部计入 `Ledger`。

> 关键正确性细节：未见对象的逐源 cap 是「已扫描源 min(dmax, 阈值)、未扫描源 dmax」，
> 且每个源仍可能缺席。对 product（中性元 1）这类聚合器，单源偏科的未见赢家可能超过
> 阈值组合——只有把缺席与在场两种情况都枚举，上界才不漏人。该陷阱由压力测试捕获并回归锁定。

### 4. 版本一致性

计算期间任一源版本变更：

- `on_drift="continue"`：继续读查询开始时固定的旧快照，记录 `drift_continue` 事件；
- `on_drift="restart"`：整次重开，状态与账本清零、重启计数 +1，记录 `drift_restart`。

任何策略都不会混合两个版本的数据，测试中分别与旧版本 / 新版本的全量基线核对一致。

### 5. 有限内存

执行器只维护已见键的每源归约标量与缺席集合，从不物化任何笛卡尔关联；
已见键数不超过各源键数之和（`TestBoundedMemory`）。

## 目录结构

```
leaderboard/
  sources.py      版本化数据源、不可变快照、一对多归约、SA/RA 原语
  scoring.py      单调聚合器、缺项规则、上下界数学、稳定并列约定
  engine.py       TA/NRA 执行器、未见上界、停止证据、成本账本、漂移处理
  baseline.py     全量关联基线、朴素局部 TopK（反例对照）、逐名核对
  datasets.py     四个内置反例数据集 + 确定性随机生成器
  app.py          标准库 HTTP API
  static/         原生 JS 网页（配置/候选/停止证据/成本/突变实验）
tests/
  test_engine.py  27 个单元测试（含上下界穷举、快照漂移、并列稳定）
  test_stress.py  1920 个随机配置的正确性压测
  test_api.py     真实 HTTP 服务的 16 项端到端检查
cli.py            命令行演示（数字全部来自实际执行）
webapp.py         网页服务入口
```

## 快速开始

```bash
# 单元测试 + 压力测试
python3 -I -m unittest discover -s tests -t . -v
python3 -I tests/test_stress.py

# 命令行演示（内置数据集、TA/NRA、漂移）
python3 -I cli.py demo
python3 -I cli.py run counterexample --mode ta --k 3
python3 -I cli.py drift

# 网页（默认 http://127.0.0.1:8000）
python3 -I webapp.py --port 8000
# API 端到端检查（服务启动后另开终端）
python3 -I tests/test_api.py
```

网页支持：配置权重/聚合器/缺项规则/K/模式/调度、展示当前候选与每轮停止证据、
模拟某源访问变慢（虚拟延迟）、查询中替换源数据观察 continue/restart、与全量关联对照。

## 实测结果（均来自当前代码的实际执行，非估算）

反例数据集 `counterexample`（3 源 × 26 键，K=3，等权 wsum）：

| 方法 | 榜单 | SA 读取 | RA 读取 | 停止规则 |
|---|---|---|---|---|
| 全量关联基线 | star, mid1, a1 | 78 | 0 | 扫完所有源 |
| **TA 执行器** | star, mid1, a1 | **41（省 47.4%）** | 74 | `threshold_bound`，UB=0.950 < 边界 1.000 |
| NRA 执行器 | star, mid1, a1 | 78 | **0** | `nra_interval_closure`，UB=0.120 |
| 朴素局部 TopK | a1, a2, b1 | — | — | **漏掉 star（真实第 1）与 mid1（真实第 2）** |

压力测试（`tests/test_stress.py`，120 种子 × 4 聚合器 × 2 缺项规则 × 2 模式 = 1920 配置）：

```
通过 1920 个随机配置，用时约 18s
其中 703 个案例实现了提前停止
SA 总读取: 执行器 104313 vs 全量 128416（节省 18.8%）
```

一个重要的工程观察：TA 虽然省下 47% 的 SA，但 74 次 RA 的代价可能让总虚拟耗时反超全量
（反例数据中 384 vs 117）。因此模块同时提供零 RA 的 NRA，并把每源 SA/RA 与延迟如实记账，
访问顺序的选择由真实读取量支撑，而非凭直觉。

## 内置数据集

- `counterexample`：局部前列漏掉真正赢家（核心反例，稀疏跨源键）。
- `one_to_many`：一对多归约防膨胀，可切 max/sum/avg/first 观察差异。
- `missing_keys`：neutral 与 exclude 两种缺项规则给出不同榜单。
- `ties`：总分并列时业务键升序的稳定约定，与源排列顺序无关。
